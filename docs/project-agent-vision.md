# Project agent

This document records the product direction established for the project agent.

- **Every project should have a persistent agent chat.** The user can return to it throughout the project to ask questions, discuss ideas, and request work.

- **The agent should have full, current project context.** It should understand the objects on the Table, Canvas content, materials, scenes, and other project information, including changes made by the user or other tools.

- **The agent should know the project’s history.** This includes the undo history and, where available, the original inputs and sources behind created objects, so it can understand both what exists and what was requested.

- **The agent should retain the context needed for an ongoing conversation.** It should remain up to date as the project changes and be able to use project history when continuing work.

- **The agent should be able to work across the app.** It can create and revise objects, add things to Canvas, run tasks, research, help with costing, and collaborate on the project more generally.

- **The project is the agent’s focus.** It can use context beyond the project, such as the shared Lab, when relevant to the work.

- **The agent should have controllable internet access.** It should be able to research information and work with outside services as needed.

- **The agent should be able to connect to MCPs and web-based tools.** This can give it access to external apps and services as part of its project work.

- **The agent should have access to a browser.** It can use websites and web-based tools to carry out tasks, including filling out vendor forms.

- **The browser should be available for the user to open and inspect.** The user can follow along or take over when needed—for example, to log in—then let the agent continue.

- **The agent’s work should be visible as much as possible.** People should be able to see its progress and the changes it makes.

- **The agent should not freeze the app while it works.** The user should be able to continue designing, with only the part of the app the agent needs held while it works.

- **Longer tasks should continue when the user changes views or switches projects.** What happens when the app itself closes remains open.

- **Proactive assistance is a possibility.** The agent may eventually notice things and offer suggestions, but how that works has not been defined.

- **Agent settings should be editable.** Provide an interface for project-level settings and potentially Lab-level settings, including the provider, model, reasoning level, and possibly a time budget.
