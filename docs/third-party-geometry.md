# Third-party polygon geometry

FORM's general sewing allowances use the C++ Clipper2 library by Angus Johnson, vendored from the official `Clipper2_2.0.1` source tag. The official [2.0.1 release](https://github.com/AngusJohnson/Clipper2/releases/tag/Clipper2_2.0.1) identifies release commit `21ebba0`. The downloaded archive is pinned by SHA-256 `2a3693aceab4aed3e39b743e038d87701acc53cf05ed7b2013aab3e0aec5287e`; its URL, file list, and hash are recorded in `Sources/CFormClipper/UPSTREAM.json`.

The vendored upstream C++ headers and engine/offset/rectangle-clipping source files retain their copyright notices and are unmodified. `Sources/CFormClipper/LICENSE` contains the complete Boost Software License 1.0. The small `form_clipper.h`/`form_clipper.cpp` C ABI is FORM code. Swift owns source topology, physical curve sampling, identity, and validation. The bridge performs only bounded polygon offset/difference/intersection and releases its allocated results through an explicit matching free call. It has no network, file, model, printer, or machine interface.

Upstream's official [offset documentation](https://angusj.com/clipper2/Docs/Units/Clipper.Offset/Classes/ClipperOffset/_Body.htm) describes orientation of outer/hole rings, the need to remove intersections before offsetting, and the fact that output path order can change. FORM validates simple source topology first, normalizes winding internally, and restores hole identity by geometry; it does not use output array positions as source IDs. [InflatePaths](https://angusj.com/clipper2/Docs/Units/Clipper/Functions/InflatePaths.htm) documents the precision/arc-tolerance arguments. FORM uses explicit integer scaling rather than relying on a floating precision default, and an explicit round-join [arc tolerance](https://angusj.com/clipper2/Docs/Units/Clipper.Offset/Classes/ClipperOffset/Properties/ArcTolerance.htm) rather than an allowance-dependent default.

The C++17 target links locally through SwiftPM; no binary download or runtime service is required. Geometry version, provenance, tolerances, supported topology, source-preserving behavior, and regression evidence should be reviewed when updating the pin. Keep the license and copyright notices with distributed source copies.
