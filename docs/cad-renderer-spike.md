# RealityKit foundation and migration spike

The renderer candidate is **RealityKit `RealityRenderer` hosted by a demand-driven native `MTKView`**, available from macOS 15. RealityKit performs mesh, PBR material, lighting, camera and render work; MetalKit supplies render targets, native view lifecycle and presentation. This is not a replacement custom graphics engine. The earlier SceneKit implementation remains the comparison baseline until all consumers pass parity.

Apple's [SceneKit transition session](https://developer.apple.com/videos/play/wwdc2025/288/) recommends RealityKit. The public [RealityRenderer](https://developer.apple.com/documentation/realitykit/realityrenderer), [MeshResource](https://developer.apple.com/documentation/realitykit/meshresource), and [OrthographicCameraComponent](https://developer.apple.com/documentation/realitykit/orthographiccameracomponent) APIs were checked against the installed SDK and exercised on the supported local Mac. Full public orthographic/offscreen behavior requires macOS 15; the deployment target is raised explicitly rather than silently substituting perspective on older systems.

## Boundary

`LabRendering` contains no SceneKit or product-document types. Mesh positions, object translations, camera position and clipping limits are Double millimeters. Its RealityKit adapter converts to meters only when creating GPU resources and transforms. Mesh-local recentering and a quantized floating origin keep small features near GPU origins without modifying document coordinates.

Stable object UUIDs and component/part IDs accompany buffers. `SceneProjection` performs projection, camera rays, plane intersection and exact triangle picking independently of the renderer. The existing world-up camera/navigation controller remains authoritative. Orthographic `verticalSpanMM` is the full span; RealityKit's scale is a half-span, so the boundary divides by 2000. The existing saved camera maps to `2 × distance × orthographicFactor × 100` mm.

Texture UVs use the top-left image origin shared by current artwork and glTF. The adapter flips decoded rows once at upload. Native hex/NSColor values use encoded sRGB; imported glTF factors use explicit linear-sRGB encoding. RealityKit's offscreen BGRA output is interpreted as Display P3 and normalized to sRGB before returning a CGImage. Tone mapping remains an explicit lighting choice; a photographic tone curve is not an RGB identity transform.

PBR channels include base color, normal, metallic, roughness, occlusion, emissive, alpha mask/blend, double-sided surfaces and depth controls. Samplers and packed-channel swizzles are explicit. Non-unit normal strength derives a normalized RGB data image without changing source bytes; that processing currently requires opaque RGB maps. Secondary UVs and vertex colors stay in source payloads, but procedural UV1 is not publicly available on this host's OS and standard PBR does not consume custom vertex color attributes automatically. Import adapters must bake supported shared UV mappings and report unresolved fidelity differences.

## Actual proof

The private proof renders the existing MERIDIAN v02 case STL (36,864 triangles / 110,592 supplied vertices) and its original editable-dial PNG through RealityKit. It produces a 1000×800 perspective capture and an 840×1000 transparent orthographic capture. A real first render exposed texture-row inversion; pixel comparison exposed the orthographic half-span conversion and the P3/sRGB boundary. These were corrected before consumer integration. The upright 12/6 and “Test Clock” artwork remain visible.

Fourteen isolated optimized tests pass, including real GPU pixels for material slots, transparent corners, physical orthographic scale, normalized source-color primaries, distinct linear/encoded factors, and source-preserving normal-strength processing, top-left image rows and GPU projection/picking at billion-millimeter world coordinates. Transform and material updates do not rebuild the mesh; a failed material update retains the prior visible geometry. Exact triangle picking returns the clock component/object, and source textures remain unchanged. The final color-normalized, image-lit orthographic case capture was 8.42 ms. This is a capture measurement, **not a claim of 60-fps interactive performance**.

A separate native-GPU stress run places 64 instances of that case (2,359,296 visible triangles). It uploads one shared mesh and one material: 4.42 MB retained mesh buffers, 19.13 ms initial placement/upload, and 165.7 MB peak process RSS. Twelve 1200×800 captures measured 17.39 ms median and 29.36 ms maximum, including scene clone, GPU completion and sRGB readback. Camera updates measured at most 0.037 ms. A separate 64-instance semantic-picking regression with 2,097,152 visible triangles measured 0.138 ms p95 and 0.140 ms maximum across 20 clicks; cached mesh bounds reject unrelated instances before triangle work. These measurements describe this fixture and offscreen path; they do not establish whole-application memory caps or viewport fps.

The native Table/event host, inset object preview, print bed/toolpaths, Study cards, project thumbnails, current-view PNG export and saved Studio shots now target this backend. The previous gesture handler and world-up camera math remain unchanged. CPU recipe geometry crosses a dedicated `GeometryPayloadAdapter` boundary with revision-based resource reuse; its historical 100-mm construction coordinates never enter the neutral API. Thin square tubes replace line primitives for grids, selection outlines and sliced paths. Saved shots preserve the requested perspective/orthographic camera and output expansion, and captures suspend while GPU work finishes. Imported/CAD snapshots await verified source preparation on a worker instead of exporting a missing object. The first integrated run passes all 378 App tests, including 19 native event-camera tests, 19 Studio tests and the actual printed-cloth corner/material proofs. Lower-level camera navigation/framing (20 tests), solved curved-pouch and cloth GPU proofs pass as well. Unrelated schema/CAD persistence failures remain with their owners; the full upgrade is not accepted until those are repaired, the stable-component regression is rerun and the new job-render/identity tests finish.

A procedural neutral softbox environment uses the public [ImageBasedLightComponent](https://developer.apple.com/documentation/realitykit/imagebasedlightcomponent) APIs and is shared between viewport instances. It provides continuous reflections for metals without fetching external imagery. Image-based light receiver references are rebound into snapshot clones, so saved output uses the same environment.

A repeated short-lived capture test exposed a host SDK coroutine-lifetime abort when directly awaiting the async `MeshResource` initializer. The backend now isolates that initializer in a cancellation-aware child task, while retaining project epoch guards. Five repeated async upload/capture lifetimes and reset safety pass on the actual GPU; this fixes every consumer centrally, without a synchronous upload fallback.

`CADReviewRenderer` now renders evaluated, uncommitted job components with a separate canonical-mm camera. Perspective, Front and Top frame all visible components; Front/Top remain orthographic. Inputs are bounded to 1–256 unique components, 256 MiB source display buffers and exact output dimensions up to 8192 per edge / 32 MP. The actual private GPU proof produces all three 360×240 transparent views with both colored components visible. The renderer does not mutate the editing camera, scene selection, durable feature model or job. The coordinator owns guarded publication of the resulting PNG and retains source/job identity for the modeling conversation.

Native computer-use camera checks confirm horizontal, vertical, diagonal and reverse drags, Shift-pan, full horizontal sweeps without an artificial wall, and whole-project named-view framing with and without selection. World-up right-axis drift is zero; a round-trip gesture sequence differs by approximately 5×10⁻¹⁷.

Private artifacts and logs are in `.local/realitykit-spike/`; they include user artwork and are not published. The isolated package uses its own scratch/cache paths, so the shared app build is not raced by spike compilation.

| Orbit / Shift-pan / named views | Existing navigation math is retained. 19 native AppKit event tests and 20 lower-level camera tests pass unchanged behavioral assertions; native computer-use sweeps and inverse gestures also pass with zero right-axis drift. |
| Live linked artwork | Real retained dial texture renders; scoped material/texture updates are available. Native source-edit/Undo remains integration acceptance. |
| Geometry reload / Undo | Transactional upload retains the previous valid record on failure; document Undo remains the existing engine's responsibility. |
| Studio / exact output | Actual perspective, orthographic, transparency and requested pixel counts tested. 19 Studio tests pass, including exact pixel dimensions, perspective/orthographic framing, source preservation and concurrent capture provenance. |
| Memory / responsiveness | Bounded retained mesh/texture/material caches, async mesh generation and project-reset generation guards implemented. Live scene/source data and captures are additional memory; benchmark the complete collection before claiming a total cap or fps target. |
| Native Table / inset / print | All native consumers are wired and 378 App tests pass; the latest job-review/identity additions and the complete upgrade suite must finish before final acceptance. |

The API spike is viable. This document does not mark the complete renderer migration or the CAD upgrade accepted merely because the new backend compiles.
