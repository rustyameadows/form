# Native CAD feature graph

`FormCADModel` is a Foundation-only Codable schema. It has no OCCT, renderer, AppKit or Core dependency. Core can inspect and validate a native document without loading an exact kernel. `FormCADModeling` evaluates that intent through the separate kernel worker.

A model has a persistent UUID, schema version, revision, name, named bounded parameters, feature nodes, output feature IDs, assumptions and unresolved measurements. Every node has a persistent UUID, label, typed operation and explicit input UUIDs. Operation payloads are checked by kind; unrelated fields and unknown scalar names are rejected. Native documents can contain primitives, planar polygon/circle/Bezier/arc profiles, extrusion/revolution and their cuts, booleans, fillet, chamfer, shell, sweep, loft, placement, linear/circular patterns, mirror, assembly and pinned imported exact bodies.

Scalar values can contain bounded arithmetic expressions using named parameters, numeric/scientific literals, parentheses, `+ - * /`, `pi` and `tau`. Evaluation is finite and bounded; it does not execute source code or support arbitrary functions. Graph validation checks duplicate/missing IDs, dependencies, cycles, input counts, physical coordinate limits, plane bases, source hashes and expression complexity before kernel work.

The evaluator computes a canonical model SHA-256 and a resolved per-node fingerprint from its operation and dependency fingerprints. Unused parameters do not invalidate geometry. Dirty nodes rebuild in dependency order; unaffected shapes reuse immutable cached handles. A complete successful result atomically becomes the model's accepted evaluation. A failed feature reports its UUID, operation, reason and earlier valid revision while retaining that valid output. Generation checks and cancellation prevent an older concurrent request from becoming the new accepted result.

A fillet/chamfer/shell using selected ordinal edges/faces records the input feature fingerprint in its topology selection. Regeneration refuses to reuse ordinals when that fingerprint changes. The caller must inspect the new topology and explicitly review the selection. All-edge operations and unique axis-planar extrema selectors are available when their semantics are suitable. Ambiguous extrema fail clearly. This is bounded semantic selection, not a claim of complete persistent topological naming.

Exact imports use relative asset paths plus SHA-256 hashes. The evaluator resolves symlinks, rejects escapes from the resource root and checks source content even on geometry cache hits. STEP assembly import preserves source names, hierarchy, repeated definitions, local/world placements and source colors in optional `importedAssemblies` metadata. Leaf feature sources additionally pin `partPath` to the original SHA/kernel version. No construction history is invented. Per-face appearance records pin the exact output feature fingerprint; topology changes cannot silently remap the source color ordinals.

Staging creates an exclusive revision directory containing the original graph, exact output BRep, optional STEP, mesh archive and manifest with hashes, measured bounds, mass properties and topology counts. It never overwrites an existing revision. Staging rechecks accepted revision after suspension points and removes a partial private stage on failure. The application must separately guard the project epoch/source revision and publish immutable project assets in one Undo transaction; evaluator acceptance alone does not authorize a document commit.

The supplied native construction examples are `clockEnclosure`, `vase`, `lamp` and `enclosure`. They use real analytical/Bezier profiles, cuts, normal-offset walls, connected bosses, bores and controlled finishing. Their assumptions and unresolved measurements remain visible in the model. Physical movement fit, electrical components, closures, fasteners and process tolerances require actual measurements.

## Native and MCP review flow

The native exact model editor shows the same staged solids that will be committed. Parameter fields remain drafts; Preview validates and regenerates, and Apply publishes the revision. The preview uses the established Table camera navigation math and drag / Shift-drag / scroll controls. Existing models reopen their original graph; imported exact bodies disclose their limited editability.

`form_cad` exposes a job-based facade. `create`/`evaluate`/`parameter`/`feature`/`import_step` produce asynchronous preview jobs, `status` reports progress/errors, and `commit` starts guarded publication of a ready job. Publication copies verified assets off the UI actor, rechecks project epoch and all source data except camera, then makes one Undo edit. Finishing an active text field is followed by another source check. Late results from cancelled/reopened projects cannot publish. An unpreviewed draft cannot apply a stale preview.

`capabilities`, `templates`, `plan`, `inspect` and `status` inspect without changing a project. `topology` returns a ready job's feature fingerprint and revision-scoped faces/edges; `clearance` measures two exact outputs. `export` writes a chosen output to STEP or BRep with exclusive destination creation. These work asynchronously and their result is available through `status`. `cancel` discards a review. For an existing object, first evaluate its `object_id`, inspect the returned ready job, then export or commit as required.

Immutable flat project assets contain content SHA-256 in their names. Original imported STEP/BRep is copied into this set and graph references are pinned to it. The representation records measured bounds/topology and both exact BRep and mesh digests. Scene loading checks both sources, allocation bounds and renderer limits in a worker. CAD body coordinates preserve their exact origin; object position and yaw are occurrence transforms. A combined mesh part preserves original triangle order for an independent triangle-to-face map without creating one draw call per CAD face.

The optional imported tree stores part/face colors as linear-sRGB RGBA. Native review shows the source hierarchy and individual exact leaf outputs. The renderer groups triangles by source color and retains a separate triangle-to-face map per material part, with bounded draw groups. Object/component color overrides update material payloads while retaining the mesh revision. Geometric STEP export remains separate from full source assembly export fidelity: original bytes are retained, while the current regenerated STEP writer produces exact body geometry without reproducing the source names/colors/tree.

Ready jobs can be observed before commit with `render`: choose perspective/front/top, exact pixel dimensions, transparency and an exclusive PNG destination. GPU capture suspends asynchronously; encoding/file work happens off the UI actor. Job token, accepted revision and project source/epoch are checked around suspension and publication. Beginning commit invalidates pending inspection tasks so late render/export feedback cannot overwrite the committed object result.

The evaluator also bounds exact feature retention: eight accepted model caches and a conservative 256 MiB topology estimate by default, separate from the 64 MiB mesh and 64 MiB STEP-source caches. It evicts least-recently accepted inactive models, exposes byte/count/eviction diagnostics, and supports explicit `forget(modelID:)`. A single oversized model rejects rather than retaining unbounded topology. Failed edits preserve the current model's prior valid revision. The topology estimate is a conservative policy heuristic, not a measurement of all OCCT allocator memory. An executed twelve-model run with a three-model policy retained three models (55,296 estimated bytes) and recorded nine evictions; an oversized pattern rejected while its earlier valid result remained accepted.

STEP assembly occurrence selectors are additionally checked against the recorded kernel version during evaluation. A kernel-version change requests source reinspection/reimport rather than assuming source occurrence paths still identify the same parts.
